[[introduction]]
== [[_introduction]] Introduction

The aim of this guide is to assist you migrating
an existing application using any version `{hibernateSearchPreviousStableVersionShort}.x` of Hibernate Search
to the latest of the `{hibernateSearchVersionShort}.x` series.

NOTE: If you think something is missing or something does not work, please link:https://hibernate.org/community[contact us].

If you're looking to migrate from an earlier version,
you should migrate step-by-step, from one minor version to the next,
following the migration guide of link:https://hibernate.org/search/documentation/migrate/[each version].

[[requirements]]
== Requirements

The requirements of Hibernate Search {hibernateSearchVersion}
are the same as those of Hibernate Search {hibernateSearchPreviousStableVersionShort}.

[[artifact-changes]]
== Artifacts

[[v5migrationhelper-removal]]
=== Hibernate Search 5 migration helper removed

The `hibernate-search-v5migrationhelper-engine` and `hibernate-search-v5migrationhelper-orm` artifacts are no longer published.
If you are still using the migration helper, you will need to migrate to the current Hibernate Search APIs.

[[elasticsearch-client-artifact]]
=== Elasticsearch REST client is no longer a transitive dependency

`hibernate-search-backend-elasticsearch` no longer depends on `hibernate-search-backend-elasticsearch-client-rest4`.
If you want to keep using the Elasticsearch REST client based on Apache HTTP Client 4,
add `org.hibernate.search:hibernate-search-backend-elasticsearch-client-rest4` explicitly to your application dependencies.

Without an additional client artifact, the Elasticsearch backend now uses its JDK HTTP client.
If exactly one additional client is available, Hibernate Search selects it automatically.
If several are available, startup fails unless you set `hibernate.search.backend.client_factory`
to `elasticsearch-rest4`, `elasticsearch-rest5`, `opensearch-rest`, or `jdk-rest`.
The value of `ElasticsearchBackendSettings.Defaults.CLIENT_FACTORY` changed from `elasticsearch-rest4` to `jdk-rest`.

The new `org.hibernate.search:hibernate-search-util-json` artifact supplies Search JSON nodes and streaming SPI.
The Elasticsearch backend brings it in transitively; direct users can declare it explicitly.

Other than these changes, the coordinates of Maven artifacts in Hibernate Search {hibernateSearchVersion}
are the same as in Hibernate Search {hibernateSearchPreviousStableVersionShort}.

[[data-format]]
== Data format and schema

[[indexes]]
=== Indexes

The index format and schema in Hibernate Search {hibernateSearchVersion}
is backward-compatible with Hibernate Search {hibernateSearchPreviousStableVersionShort}:
older indexes can be read from and written to without reindexing.

[[outboxpolling]]
=== Outbox polling database tables

The event and agent database tables used for
link:https://docs.hibernate.org/search/{hibernateSearchVersionShort}/reference/en-US/html_single/#coordination-database-polling[outbox-polling]
in Hibernate Search {hibernateSearchVersion}
are backward-compatible with Hibernate Search {hibernateSearchPreviousStableVersionShort}:
no database schema update is necessary for these tables.

[[configuration]]
== Configuration

The configuration properties in Hibernate Search {hibernateSearchVersion}, in general,
are backward-compatible with Hibernate Search {hibernateSearchPreviousStableVersionShort},
with the following exceptions:

* The deprecated `hibernate.search.automatic_indexing.*` configuration properties have been removed:
** `hibernate.search.automatic_indexing.enabled` -- use `hibernate.search.indexing.listeners.enabled` instead.
** `hibernate.search.automatic_indexing.strategy` -- use `hibernate.search.indexing.listeners.enabled` instead (note: it expects a boolean value, not a strategy name).
** `hibernate.search.automatic_indexing.synchronization.strategy` -- use `hibernate.search.indexing.plan.synchronization.strategy` instead.
** `hibernate.search.automatic_indexing.enable_dirty_check` -- removed without replacement; dirty check is now always performed.

[[api]]
== API

The https://hibernate.org/community/compatibility-policy/#code-categorization[API]
in Hibernate Search {hibernateSearchVersion}
is, in general, backward-compatible with Hibernate Search {hibernateSearchPreviousStableVersionShort},
with the following exceptions:

* Both JPA and Hibernate ORM query adapters alongside with `Search.toJpaQuery()` and `Search.toOrmQuery()`
have been removed after being deprecated for a while now.
Use Hibernate Search query DSL API to work with your query and results.

* The `AutomaticIndexingSynchronizationStrategy` interface, `AutomaticIndexingSynchronizationStrategyNames`,
`AutomaticIndexingSynchronizationConfigurationContext`, and `AutomaticIndexingStrategyName` enum have been removed.
Use `IndexingPlanSynchronizationStrategy` and related types instead.
The `SearchSession#automaticIndexingSynchronizationStrategy(...)` method has been removed;
use `SearchSession#indexingPlanSynchronizationStrategy(...)` instead.

* The `org.hibernate.search.mapper.orm.common.EntityReference` interface has been removed.
Use `org.hibernate.search.engine.common.EntityReference` instead.
The `org.hibernate.search.mapper.orm.work.SearchIndexingPlanExecutionReport` interface has been removed;
use `org.hibernate.search.mapper.pojo.work.SearchIndexingPlanExecutionReport` instead.

* The deprecated converter interfaces with "Field" in the name have been removed:
`FromDocumentFieldValueConverter`, `ToDocumentFieldValueConverter`,
`FromDocumentFieldValueConvertContext`, `ToDocumentFieldValueConvertContext`,
`FromDocumentFieldValueConvertContextExtension`, `ToDocumentFieldValueConvertContextExtension`.
Use their renamed counterparts: `FromDocumentValueConverter`, `ToDocumentValueConverter`, etc.

* The `entityReferences()` and `entityReference(Object)` methods on `EntityIndexingFailureContext`
and `MassIndexingEntityFailureContext` have been removed.
Use `failingEntityReferences()` and `failingEntityReference(EntityReference)` instead.

* The `ValueReadHandleFactory` SPI interface has been removed. Use `ValueHandleFactory` instead.

* The `Version.getVersionString()` method has been removed. Use `Version.versionString()` instead.

* The deprecated client-specific constants in `ElasticsearchBackendSettings` and its `Defaults` class have been removed.
Use the corresponding constants in `ClientRest4ElasticsearchBackendClientSettings` for the REST4 client,
or in the settings class for your chosen client.
The configuration property keys themselves have not changed.

* The deprecated `org.hibernate.search.backend.elasticsearch.client.ElasticsearchHttpClientConfigurer`
and `org.hibernate.search.backend.elasticsearch.client.ElasticsearchHttpClientConfigurationContext` interfaces have been removed.
For the REST4 client, use the corresponding interfaces in `org.hibernate.search.backend.elasticsearch.client.rest4`.
To replace the old context's `configuredVersion()` method, read `ElasticsearchBackendSettings.VERSION`
from `configurationPropertySource()`.

[[elasticsearch-json]]
=== Elasticsearch JSON API migration

Replace imports of Gson JSON nodes in native fields, raw results and extensions with
`org.hibernate.search.util.json.JsonElement`, `JsonObject`, `JsonArray`, `JsonPrimitive` and `JsonNull`.
Primary method names stay unchanged. Update generics and recompile applications:
changed return types and client SPIs are source and binary incompatible.

* `ElasticsearchSearchResult.responseBody()` and both `ElasticsearchSearchQuery.explain(...)` overloads return Search `JsonObject`.
* Projection factory `source()`, `explanation()` and `jsonHit()` return `ProjectionFinalStep<JsonObject>`.
* Native aggregation `fromJson(...)` returns `AggregationFinalStep<JsonObject>`, including the deprecated Gson input overload.
* `ElasticsearchSearchRequestTransformerContext.body()` returns a mutable Search `JsonObject` and keeps copy-on-first-access isolation.
* Native field values use Search `JsonElement`: update bridge conversions, field references and projected value types.
* `ElasticsearchIndexSchemaExport.bodyParts()` returns `List<JsonObject>`.

Native predicate, sort, aggregation and mapping methods accept Search objects.
String overloads remain and parse the original characters using strict JSON grammar;
single-quoted strings/property names and comments are no longer accepted.
There is no legacy output facade. Deprecated Gson input bridges remain temporarily.
The public deprecated `org.hibernate.search.backend.elasticsearch.gson.GsonJsonConversion`
converts elements/objects/arrays in either direction through direct traversal,
preserving valid number lexemes, member order and nulls while allocating an independent tree.
It never serializes/reparses, but each conversion still costs traversal and allocation.
All bridges and this utility will be removed together in a future breaking release.
Literal null arguments may require an explicit cast to select the intended overload;
input validation still applies.

Do not mutate raw returned trees; copy them with `deepCopy()` first.
Submitted request trees must remain unchanged until signing, consumption and retries finish.
The new accessor SPI is strict by default: opt into `unwrapSingletonArrays()` at every
intermediate/terminal location requiring the old implicit singleton-array adaptation.
`asArray()` does not flatten nested arrays. Numeric narrowing remains a separate policy.
Adapted absence/multiple-element-array failures now have contextual exceptions;
numeric equality/hashing and JSON grammar include intentional corrections.
See the link:{hibernateSearchDocUrl}#backend-elasticsearch-json[JSON reference]
for compiled examples, creation/write behavior, ownership and transport limits.

[[spi]]
== SPI

The https://hibernate.org/community/compatibility-policy/#code-categorization[SPI]
in Hibernate Search {hibernateSearchVersion}
is, in general, backward-compatible with Hibernate Search {hibernateSearchPreviousStableVersionShort},
with the following exceptions:

* The `AutomaticIndexingStrategyStartContext` SPI interface has been removed. It was introduced by mistake and was never used.

* The `ValueReadHandleFactory` SPI interface has been removed. Use `ValueHandleFactory` instead.

* The `ElasticsearchBackendImplSettings` class (both `cfg.impl` and `cfg.spi` variants) has been removed.

* Custom `ElasticsearchClientFactory.create(...)` implementations now receive
`org.hibernate.search.backend.elasticsearch.client.common.json.spi.JsonProvider` instead of Gson services.
Request `bodyParts()` uses `List<JsonObject>`, builder `body(...)` accepts Search `JsonObject`,
and response `body()` returns Search `JsonObject`.
Use the supplied codec service for registered types and library-neutral parser/cursor contracts for streaming.
Unknown types fail rather than falling back to reflection. Keep independent parser/cursor state per attempt,
close on terminal events, and preserve caller-buffer ownership and backpressure.
Signing and interceptors remain synchronous; incremental JSON imposes no automatic worker hop or event-loop latency bound.
The link:{hibernateSearchDocUrl}#backend-elasticsearch-json-custom-clients[custom-client reference]
details lifecycle, stable content length, client-owned diagnostic/compression boundaries and cancellation limits.


* The `HibernateOrmQueryLoader.createMultiIdentifierLoadAccess(SessionImplementor)` method has been removed.
Use `HibernateOrmQueryLoader.findMultiple(SessionImplementor, List, FindOption...)` instead.

* The `HibernateOrmLoadingSessionContext.session()` method now returns `SharedSessionContractImplementor`
instead of `SessionImplementor`, and has been renamed to `sessionImplementor()`.
This allows the loading context to work with both `Session` and `StatelessSession`.

[[api-deprecations]]
=== Deprecations

* The `HibernateOrmSessionContext.session()` method returning `Session` has been deprecated.
Use `HibernateOrmSessionContext.sessionContract()` instead, which returns `SharedSessionContract`
and works with both `Session` and `StatelessSession`.

[[behavior]]
== Behavior

The behavior of Hibernate Search {hibernateSearchVersion}
is, in general, backward-compatible with Hibernate Search {hibernateSearchPreviousStableVersionShort},
with the following exception:

* Hibernate Search no longer wraps exceptions thrown by property getters or constructor invocations
in a `SearchException` with an "Exception while invoking" message.
Property getter exceptions pass through unchanged,
while constructor invocation exceptions are propagated as provided by Hibernate Accessor.
Higher-level indexing operations may still add their usual contextual exceptions.
Update exception handlers and tests that rely on the previous wrapper or cause chain.
